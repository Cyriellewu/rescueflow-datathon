# RescueNYC

IBM Z Datathon 2026 · Theme 1: Real-Time AI for Critical Decisions.

**See the queue before the delay.** RescueNYC replays real FDNY EMS dispatch records in time
order, reconstructs how many calls were waiting for an ambulance at each moment, and warns an
hour ahead where the high-acuity dispatch queue is likely to back up, separating dispatch-related
from travel-related pressure. A discrete-event policy lab then tests whether acting on that
warning beats acting on the queue itself, under the same resources. Training, scoring and
simulation run on IBM LinuxONE.

Historical replay of published records, not a live 911 feed. Research prototype, not clinical
dispatch.

## Run the dashboard (quickest path)

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
# real data (about 12 min for 2023-2026 with the API; months already on disk are skipped)
.venv/bin/python scripts/fetch_data.py --start 2023-01-01
.venv/bin/python scripts/run_pipeline.py --raw data/raw --val-start 2025-07-01 --test-start 2026-01-01 --target dispatch_low --benchmark
.venv/bin/python scripts/run_policy_lab.py --raw data/raw --seeds 20
.venv/bin/python scripts/find_demo_moments.py --art artifacts
RESCUENYC_ARTIFACTS=artifacts .venv/bin/python -m uvicorn rescueflow.api:app --port 8000
# open http://localhost:8000
```

No data yet? Replace the three `--raw data/raw` runs with `--synthetic` (same scripts; the dashboard
then shows a SYNTHETIC banner). The pipeline takes about a minute on a laptop, the lab about two.

What you get at `http://localhost:8000`:

- **Overview · what the record shows** — calls per hour vs the low-acuity queue by borough and year,
  where the added response time goes (dispatch vs travel), and how local stress is.
- **Early warning · replay** — pick an hour (the buttons jump to onsets the model caught); each
  borough card shows the predicted risk and band, the bottleneck tag, the action recommendation,
  the verified briefing, the real queue state at that hour, and the realized outcome. Below: a map of
  real incident density by ZIP coloured by the hour's borough band (hospitals real, ambulance bases
  an explicit assumption), and the 48-hour risk chart.
- **Policy lab · simulation** — two simulated worlds side by side for the evaluation week, the
  handover shock shaded, and the experiment tables (baseline / reactive / AI-warned reserves).

API routes behind it: `/health`, `/risk?at=`, `/replay`, `/evaluation`, `/benchmark`, `/moments`,
`/lab`, `/lab/series`, `/overview`, `/spatial`. The map needs `spatial/spatial_data/` (committed;
rebuild with `spatial/build_spatial.py`).

On the LinuxONE VM: `cd /opt/rescuenyc && NATIVE=1 TARGET=dispatch_low bash scripts/setup_vm.sh`
runs everything with the system Python (apt pandas/scikit-learn; xgboost is unavailable on s390x and
the code falls back to `HistGradientBoostingClassifier`), starts the API on port 8000 and opens the
firewall. Without `NATIVE=1` it builds the container if Docker or Podman can pull the LinuxONE ML
image. Finished steps are skipped on rerun; `FORCE=1` redoes them.

## Run it (step by step)

On a laptop (NYC Open Data):

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/fetch_data.py --start 2023-01-01   # → data/raw/incidents_YYYY-MM.csv, resumable
scp -r data/raw <vm>:/opt/rescuenyc/data/
```

Right after the download, check the data on the laptop (seconds):
`python scripts/check_raw.py data/raw` — months present, timestamp null rates, whether held calls
really wait longer, severity codes per year.

On the LinuxONE VM, one command does everything below (build, train, lab, reports, API, port,
evidence; re-runnable): `bash scripts/setup_vm.sh`. Step by step:

```bash
python scripts/run_pipeline.py --raw data/raw \
    --val-start 2025-07-01 --test-start 2026-01-01 --benchmark   # features, model, evaluation, benchmark
python scripts/run_policy_lab.py --raw data/raw --seeds 20
python scripts/write_report.py --art artifacts                     # docs/evaluation.md, docs/data_audit.md
python scripts/find_demo_moments.py --art artifacts                # caught / missed onsets for the video
python scripts/nnpa_bench.py --art artifacts                       # NNPA vs CPU timing, if the VM exposes it
bash scripts/verify_linuxone.sh                                    # platform evidence
docker build -t rescuenyc . && docker run -d -p 8000:8000 -v $PWD/artifacts:/app/artifacts rescuenyc
# open http://<vm-ip>:8000  (or ssh -L 8000:localhost:8000 <vm> and open localhost:8000)
```

Optional GenAI briefing (llama.cpp ships in the L1CC image; on s390x the GGUF must be
big-endian): `RESCUENYC_LLM=/path/model.gguf` makes `/risk` ask the local model for the note;
any note with a number or borough not in the model output is rejected and the template is used.
`python scripts/eval_briefings.py --art artifacts` reports the rejection rate and latency.

No data at hand? `--synthetic` on the two run scripts uses a labeled synthetic simulator, and
the dashboard shows a SYNTHETIC banner. Tests: `.venv/bin/python -m pytest -q`.

## Layout

| Path | What it does |
|---|---|
| `rescueflow/data.py` | Clean raw rows, recompute durations from timestamps, validity bounds, audit |
| `rescueflow/stream.py` | Replay engine: unassigned backlog, held calls, units at hospital at each hour |
| `rescueflow/features.py` | Leakage-safe borough-hour features and the trailing-baseline label |
| `rescueflow/model.py` | xgboost, baselines, evaluation, cascade test, lead time |
| `rescueflow/briefing.py` | Operator note and the verifier that rejects unsupported numbers |
| `rescueflow/des.py` | Discrete-event policy lab (fleet, handover, reserves, paired experiments) |
| `rescueflow/api.py`, `app/` | FastAPI service and dashboard |
| `rescueflow/sim.py` | SYNTHETIC incident generator for tests and demo mode only |

## Limitations

See the end of [`docs/evaluation.md`](docs/evaluation.md). In short: replay, not live; the backlog
is reconstructed after the fact; FDNY's response measure is not the Comptroller's end-to-end time;
bottleneck tags are indicators, not causes; policy-lab results depend on stated scenario
assumptions.
